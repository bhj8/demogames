# A 方向 · 实机迭代 02

目标原文：你自己做自己优化自己迭代，你给我看的效果图这么好看，实机我也希望能看到！加油gpt

本轮在当前网页游戏上连续调整和检查了光照、造型、动作、场景与开销。没有生成新的概念图来代替实机结果。

## 已落地

- render.js / tune.js：暖冷天空渐变、方向光、启动时一次生成的建筑地面投影，以及整批敌人一次绘制的脚下阴影。交叠阴影通过模板缓冲避免反复加深。没有实时阴影贴图。
- render.js / game.js：普通、重型、吐酸、冲撞、Boss 均使用切面造型。爆裂更宽、电导更窄，保持原头部中心与判定参数。加入深色脸部和少量眼部色块；降低常驻整身变异发光，保留战斗前摇与受击反馈。
- render.js / game.js：顶点动画驱动腿部迈步与手臂摆动，跟随实际位移速度，停止与复用时归零。维持每只敌人一个主体绘制，不额外拆成多个肢体节点。
- weapon.js：加宽前护木与骨色护箍、添加握持手与瞄具、调整腰射角度；瞄准时回到原正向姿态。固定枪械零件按材质合并，枪机、弹匣和换弹手继续独立运动，支撑手在换弹时隐藏并恢复。
- city-scale.js：补齐实心建筑侧墙窗格、墙脚与屋顶收边、商铺展示窗。多视角检查发现开放框架不应有窗格，已限定装饰仅用于实心建筑。
- city-scale.js：修正旧人行道贯穿十字路口的问题。视觉路面恢复贯通；这些对象依旧无碰撞，不修改路线、导航与战斗数据。

没有新增项目依赖、下载贴图或修改 Godot 设置。未修改既有 TODO.md 内容，也没有操作 _worktrees/。

## 验证

verify.cjs 可用已有 Playwright + Node 20 以上环境运行，不会安装依赖。PLAYWRIGHT_MODULE 可指向已有安装，CHROME_EXE 可指向已安装 Chrome。当前机器默认 node 是 16，因此实际使用工具自带的新版 Node，未升级用户环境。

verification.json 记录通过项：全部敌人几何与着色器、六器官显示、真实 fire/tryReload、弹匣退出与恢复、支撑手恢复、步态、对象池回收后阴影移除、120/900 敌人绘制。现有 _todo13check.html 为 ALLPASS。未出现页面脚本或游戏循环错误。碰撞实体仍为 34。

| 120 只普通尸，六器官 | 171 | 44,680 |

这两项清空初始敌人后放置整齐密集队列，关闭主体视锥剔除以确保压力，不能与上一轮不同布置/器官状态的数字直接相减。

额外正常逻辑短测见 frame-sample.json：1280×720，RTX 2070 SUPER / Chrome D3D11，900 初始敌人，结束时导演额外生成至 901。预热后采样 89 帧，帧间隔中位数 18 ms，P95 约 18.1 ms，没有循环错误。短测不覆盖完整十二分钟、复杂连锁、其他设备或长期稳定帧率。
