## 0. 设计结论

当前问题不是“后坐或震屏参数偏小”，而是原始 Void Protocol 的枪械执行框架没有继承下来。

原版拥有：

- 弹簧式枪身后坐与相机回弹；
- 鼠标惯性摆动、横纵步态、静止呼吸；
- 枪机、弹匣、泵动/拉栓等独立机械部件；
- 外焰、核心焰、瞬时枪口灯；
- 从真实枪口出发的曳光；
- 抛壳、落地声音与掉落弹匣；
- 分阶段换弹事件；
- ADS和瞄具；
- 普通命中、弱点命中、击杀三态反馈；
- 枪口爆音、机械声、弹壳、退匣、插匣、拉栓等分层声音。

当前版本主要只有：

- 整把枪沿 Z 轴后退并绕 X 轴抬起；
- 一个很小、很短的球形枪口闪光；
- 单层合成枪声；
- 计时器式换弹；
- 高速飞行的小球子弹；
- 固定准星；
- 没有抛壳、枪机、真实弹匣动作和普通命中/击杀标记。

枪感必须重新形成完整反馈链：

**扣扳机 → 枪械动作 → 枪口与弹道 → 命中/击杀 → 敌人反应 → 枪械回位 → 弹匣与换弹**

目标不是照搬旧版七把武器，而是把旧版已经验证过的执行底座迁回当前“一把枪持续进化”的产品。

## 1. 技术结构：表现层与伤害层解耦

- [ ] 建立独立的 WeaponPresentation / WeaponFX 层，推荐新增 js/weapon.js，避免继续把枪械表现堆进 game.js。
- [ ] 表现层只消费事件，不拥有伤害、敌人生命和升级抽取规则。
- [ ] game.js / combat.js 在确定事件发生后向表现层发送结构化事件。
- [ ] 所有枪感参数集中放入 tune.js 的 WEAPON_FX，不允许散落魔法数字。
- [ ] 当前共同变异产生的 gunOrgans 必须继续兼容新的枪械骨架。

建议事件：

| 事件 | 最低数据 |
|---|---|
| shot | muzzleIndex、isLastRound、pellets、overclock、当前构筑 |
| empty | 当前弹匣状态 |
| reloadStart | 换弹总时长 |
| magOut | 旧弹匣 |
| magIn | 新弹匣与容量 |
| bolt | 枪机/上膛 |
| reloadEnd | 恢复射击 |
| hit | normal / weak / armor |
| kill | normal / weak |
| buildChanged | 当前改装与共同变异 |

玩家输入产生的枪械反馈属于最高优先级；即使后期世界特效超载，也不能把玩家自己的枪声、枪口焰、准星反馈或关键换弹事件裁掉。

## 2. P0：可驱动的枪械骨架

当前枪是多个 Mesh 放进一个 Group，但重要部件没有被保存为可独立驱动的引用。

重建 WeaponRig：

- [ ] root：整把枪的姿态。
- [ ] body：主机匣。
- [ ] bolt / slide：每枪往复与空仓锁定。
- [ ] magazine：退匣、插匣和扩容外观。
- [ ] hand：换弹时跟随弹匣与枪机。
- [ ] muzzlePrimary：主枪口。
- [ ] muzzleSecondary：双联升级后启用。
- [ ] flashOuter：外层火焰。
- [ ] flashCore：高亮核心。
- [ ] muzzleLight：短时枪口照明。
- [ ] ammoScreen：枪上的弹量显示，可复用原版思路。
- [ ] gunOrgans：继续挂在 body/root 下，不因重构丢失共同变异外观。

骨架完成后，各部件必须能由事件单独驱动，不能再通过移动整把枪假装完成所有机械动作。

## 3. P0：枪身动力学

### 3.1 每枪后坐

把当前单一 recoil 值拆成至少两个通道：

- shotKick：每枪产生的快速冲击与回弹；
- sustainedClimb：持续射击形成的较慢累积趋势。

- [ ] 每枪先快速向后压枪并抬起。
- [ ] 枪机以比枪身更快的速度后退和复位。
- [ ] 回位使用带速度的弹簧，而不是单调 smooth 到 0。
- [ ] 回位允许极轻微越过静止点再稳定，避免塑料插值感。
- [ ] 连续射击时仍能看见一发一发的机械周期，不能变成一把保持倾斜的静态枪。
- [ ] 单发冲击、持续累积与回位参数分别可调。

### 3.2 移动、转身与呼吸

当前使用 p.vel.x 驱动横向枪摆；这是世界坐标，玩家转向后运动反馈会改变含义。

- [ ] 将玩家速度投影到摄像机 right / forward，使用本地横向和纵向速度。
- [ ] 前进、后退、横移分别影响枪械位置与旋转。
- [ ] 步态同时包含横向与纵向闭环，不只做垂直正弦。
- [ ] 鼠标移动给枪械加入有惯性的反向 sway，停止转身后自然回位。
- [ ] 静止时加入极轻的呼吸动态。
- [ ] 冲刺时枪械下降并偏转，结束后弹性恢复。
- [ ] 换弹、冲刺、瞄准姿态使用 pose weight 混合，不直接互相覆盖坐标。

## 4. P0：震感与镜头纪律

之前版本已经验证：随机相机位置抖动容易眩晕。不能通过恢复大幅 shake 解决枪感。

- [ ] 每枪只给相机很小、方向确定的 pitch / yaw 冲击。
- [ ] 禁止每枪随机平移相机。
- [ ] 禁止持续自动射击时高频随机 roll。
- [ ] 主要力量由枪模运动、机械部件、声音、枪口光和命中反应承担。
- [ ] cameraRecoilScale 与 viewmodelRecoilScale 必须独立。
- [ ] Debug 面板提供相机反馈倍率，可快速验证“有力但不晕”的区间。
- [ ] 连续射击十秒仍能稳定追踪目标，不因镜头噪声丢失信息。

所谓震感来自多层反馈在同一时刻对齐，而不是画面随机乱晃。

## 5. P0：枪口、弹道和射出去的“弹数”

当前主弹是半径很小的球体，速度很高，每帧可以跨越数米。碰撞存在，但视觉上近似没有子弹飞出。

### 5.1 枪口表现

- [ ] 球形闪光改为外焰 + 核心焰。
- [ ] 外焰每枪轻微随机旋转和缩放，避免机械重复。
- [ ] 核心焰更短、更亮。
- [ ] 增加极短的枪口 PointLight，让枪身和附近地面获得一次同步闪光。
- [ ] 枪口效果从真实 muzzle 节点发出。
- [ ] 高频射击时限制累计亮度，不能持续遮挡准星，但也不能缩到玩家看不见。

### 5.2 弹道可读性

- [ ] 保留当前物理子弹与扫掠碰撞。
- [ ] 为主弹增加短暂、细长的曳光尾迹，而不是只画一个小球。
- [ ] 曳光从真实枪口出发，弹道判定仍从准星方向收敛，避免枪口偏移导致“瞄哪打不到哪”。
- [ ] 双联枪管产生两个可辨识枪口与两条曳光。
- [ ] 巨化让弹迹更粗、更重，但不遮挡目标。
- [ ] 分裂弹使用共同变异颜色，与主弹明确区分。
- [ ] 贯穿时同一条弹迹应连续通过目标，而不是每次命中看起来重新生成。
- [ ] 枪口焰、曳光和命中火花在时间上连续，形成“枪口 → 路径 → 目标”的完整方向感。

## 6. P0：弹匣不是资源压力，而是射击节奏

当前产品仍然保留无限备弹，不引入有限备弹和捡子弹经济。但无限备弹不等于弹匣可以没有物理性。

### 6.1 HUD与枪上读数

- [ ] HUD明确显示“当前弹匣 / ∞”，不要再用“30 / 30”制造总弹药只有30发的误解。
- [ ] 换弹期间保留当前数字，不要整段替换为“换弹”两个字。
- [ ] 换弹进度使用独立条或环显示。
- [ ] 每发射击时数字与枪械动作同帧减少。
- [ ] 低弹量时颜色逐渐转暖。
- [ ] 最后一发有独立视觉/声音提示，但不做妨碍射击的弹窗。
- [ ] 枪上的 ammoScreen 与HUD保持一致。
- [ ] 扩容弹匣后容量显示和弹匣外观同时变化。

### 6.2 空仓状态

- [ ] 最后一发射出后，枪机停在后方。
- [ ] 空仓扣动扳机播放独立 dry click。
- [ ] 自动换弹可以保留。
- [ ] 自动换弹开始前保留一个极短、可感知的空仓瞬间，使最后一发具有结束感。
- [ ] 无限供弹 Buff 生效时，枪机、计数器和换弹状态都必须正确切换，不能只阻止 ammo--。

### 6.3 分阶段换弹

把单一 reloadT 改成可读的事件序列：

1. 枪械下沉；
2. 释放旧弹匣；
3. 旧弹匣掉落；
4. 新弹匣进入；
5. 弹量在 magIn 事件更新；
6. 拉枪机 / 拍释放钮；
7. 枪械恢复射击姿态。

- [ ] 退匣、插匣、拉栓分别有动作和声音。
- [ ] 弹匣作为池化对象掉落并短暂保留。
- [ ] 弹量不能在动作开始时提前恢复。
- [ ] 弹量在 magIn 后可以显示已装入，但直到 reloadEnd 才允许射击。
- [ ] 快速装填升级按同一比例加速整套动作和事件点，不允许动作与实际计时错位。
- [ ] 换弹结束必须有明确的机械闭合感。

## 7. P0：抛壳与机械循环

- [ ] 每发主枪射击驱动 bolt / slide 往复。
- [ ] 每发生成一枚池化弹壳，从抛壳口向右上方飞出。

- [ ] 后期高射速时可以减少远处弹壳落地声音，但不能取消枪机动作。
- [ ] 超频时枪机循环速度与射击节奏同步提升。
- [ ] 双联、巨化等构筑可改变抛壳尺寸或频率，但不制造性能爆炸。

## 8. P0：枪声必须是分层且不可被吞掉的

当前枪声主要由一次方波和一次噪声组成，并且受到全局 voice cap 限制。尸潮与连锁特效高负载时，玩家自己的枪声可能被跳过。

每枪至少包含：

- muzzle transient：枪口爆发；
- mechanical click：枪机与撞针；
- body：决定枪体重量；
- tail：很短的空间尾音；
- casing：延迟出现的世界落地声。

任务：

- [ ] 玩家枪声使用独立高优先级通道，不因世界音效 voice cap 被静音。
- [ ] 同一把枪每枪有非常轻微的音高和响度变化，避免机关枪式复制粘贴。
- [ ] 射速提高时声音仍保持离散节奏，不糊成持续蜂鸣。
- [ ] 最后一发、空仓、退匣、插匣、拉栓都有不同声音。
- [ ] 普通命中、弱点命中和击杀声音与枪声错层混音，三者都能听见。
- [ ] 爆炸、闪电等构筑特效不得盖过玩家输入的首要确认音。

## 9. P0：命中与敌人反应接入枪械闭环

弱点碰撞和三态反馈已经写在 todo.md 末尾，本文件不重复实现另一套规则，只负责接入并补齐普通射击闭环。

- [ ] 普通命中：白色小型命中标记。
- [ ] 弱点命中：金色、更大的命中标记。
- [ ] 普通击杀：红色击杀标记。
- [ ] 弱点击杀：红金组合或二段脉冲。
- [ ] 护甲命中：独立的硬质火花和声音，不能看起来像正常造成伤害。
- [ ] 敌人受击产生短暂材质闪光。
- [ ] 命中点粒子颜色与命中类型一致。

不依赖伤害数字，玩家也应该能判断刚才是打空、命中身体、命中弱点、击中护甲还是完成击杀。

## 11. P1：升级必须改变枪的“身体”，不只改变计算

当前只有一把枪，需要由升级承担原版多武器提供的节奏变化。

| 改装 / 变异 | 必须同步变化的表现 |
|---|---|
| 大口径 | 更重的枪口爆音、枪口焰、枪身单发冲击与弹壳 |
| 轻量枪机 | 枪机循环、声音节奏和枪口频率同步加快 |
| 扩容弹匣 | 弹匣模型变大或改变形态；枪上和HUD容量更新 |
| 快速装填 | 全套换弹动作和事件同步加速 |
| 稳定框架 | 枪模后坐、鼠标 sway 和准星张开幅度均降低 |
| 瞄准模块 | 稳枪姿态和弱点命中反馈强化，但不制造第二套瞄准规则 |
| 双联枪管 | 第二枪口、第二枪口焰和第二条曳光真实出现 |
| 超频 | 枪机、声音、血管发光和射击节奏逐步加速 |
| 分裂 | 主弹命中后清楚看见分裂弹从命中点飞出 |
| 骨化 | 弹迹与贯穿反馈更硬、更连续 |
| 电导 | 命中累计和触发闪电有清晰的枪体电荷反馈 |
| 巨化 | 枪口、弹迹、抛壳和单发冲击整体变重 |

- [ ] buildChanged 后重新计算表现配置。
- [ ] 外观变化、动画变化和实际机制必须同步生效。
- [ ] 升级后玩家无需打开面板，也能从枪的运动和声音察觉变化。
- [ ] 构筑效果不得靠无限增加屏幕震动表达。

## 14. 验收清单

### 不打怪也成立

- [ ] 在没有敌人的实验场里，单纯向墙射击依然能感到每一发的起点、冲击、机械循环与回位。
- [ ] 玩家能看见枪口、曳光和落点属于同一发射击。
- [ ] 连续射击时每发仍可辨认，不会变成一把静止倾斜、持续发光的枪。
- [ ] 停止射击后枪械自然回位，没有线性插值感。

### 震感但不眩晕

- [ ] 枪模反馈明显强于当前版本。
- [ ] 相机反馈方向确定，不存在高频随机平移。
- [ ] 连续射击十秒仍能稳定追踪目标。
- [ ] 玩家关闭或降低相机后坐后，枪械自身仍然有力。

### 弹匣与换弹

- [ ] HUD明确表达当前弹匣和无限备弹。
