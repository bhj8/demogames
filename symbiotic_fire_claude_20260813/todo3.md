## 0. 产品结论

本轮不是“给平地加几栋楼”，而是把地图、移动、尸潮和枪械重新咬合成第二根核心支柱：

> 玩家在街道、建筑立面和屋顶之间持续流动，利用跑酷摆脱尸潮、创造射击窗口，再主动回到危险区域抢经验和资源。

目标产品表达：

> 一款 12 分钟一局，在立体丧尸城市中飞檐走壁、边移动边进化枪械的第一人称尸潮幸存者。

目标参考比例：

- 60%《消逝的光芒》：自然、宽容、容易读懂的第一人称攀爬与翻越。
- 25%《泰坦陨落 2》：移动具有连续动量，并且移动和射击能够同时发生。
- 15%《虐杀原形》：玩家不被普通墙体和高低差轻易阻断，具有轻度超人感。
- 《Apex》作为地图元素参考：滑索、跳板、楼层连接和清晰的城市路线设计。

本轮核心循环：

**街面收割 → 尸潮合围 → 登墙上楼 → 移动射击 → 屋顶抢资源 → 特殊感染者封锁高处 → 跳回街面继续收割**

核心戏剧冲突：

- 留在地面更容易获得经验、医疗和密集击杀，但更容易被包围。
- 前往高处可以创造空间和射击角度，但高处不能成为永久安全区。
- 停下来更容易精确射击，持续移动才更容易活下来。
- 玩家不是单纯逃跑，而是在利用路线重组尸潮、制造下一次杀戮窗口。

## 2. P0：玩家基础机动系统

所有关键路线必须由基础能力完成，不能要求玩家随机抽到某张卡才能离开街道或抵达屋顶。

### 2.1 基础动作

- [ ] 跳跃。
- [ ] 自动翻越汽车、护栏、矮墙和低障碍。
- [ ] 自动抓边并爬上阳台、平台和屋顶。
- [ ] 短距离垂直登墙，用于抵达可抓取边缘。
- [ ] 短距离横向墙跑。
- [ ] 地面与空中共用一次方向冲刺。
- [ ] 奔跑后滑铲。
- [ ] 滑索、跳板等地图机动装置。
- [ ] 第一版不设置跑酷耐力。
- [ ] 第一版不造成坠落伤害。
- [ ] 落地可以有镜头、枪模、音效和尘土反馈，但不能产生长时间硬直。

### 2.2 输入原则

建议保持低操作负担：

- Space：普通跳跃；持续按住时，根据环境自动翻越、抓边或登墙。
- Shift：沿当前移动输入方向冲刺；在空中时变为空中冲刺。
- 奔跑中按蹲伏：进入滑铲。
- 滑索使用现有交互键或近距离自动吸附，二者择一并保持全局一致。
- 墙跑通过“空中靠近可跑墙面＋持续前进”自动进入，不增加独立墙跑键。

玩家的主要决策应该是“走哪条路线”，而不是记忆复杂按键组合。

### 2.3 第一轮建议参数

所有数值必须放入集中配置，并允许 Debug 热调：

| 参数 | 首轮建议 |
|---|---:|
| 重力 | 20～22 m/s² |
| 起跳速度 | 8.0～8.5 m/s |
| 土狼时间 | 0.12 秒 |
| 跳跃输入缓存 | 0.15 秒 |
| 自动翻越高度 | ≤1.2 米 |
| 抓边攀爬高度 | ≤2.4 米 |
| 垂直登墙持续 | 0.45～0.65 秒 |
| 横向墙跑上限 | 0.9～1.2 秒 |
| 空中冲刺次数 | 1 次，接触稳定地面后恢复 |
| 空中冲刺持续 | 0.16～0.22 秒 |
| 滑铲基础持续 | 0.55～0.8 秒 |

这些只是首轮起点。手感目标比具体数值更重要：动作要宽容、不断流、不需要精确对准一个像素的边缘。

### 2.4 移动与枪械不得互相中断

- [ ] 跳跃、下落、墙跑、滑索和空中冲刺期间允许射击。
- [ ] 跳跃、下落和普通墙跑期间允许换弹继续推进。
- [ ] 自动翻越与抓边动画尽量短，不长时间锁枪。
- [ ] 准星在空中仍然可用，不施加严重的空中散布惩罚。
- [ ] 冲刺与滑铲如何影响射击沿用统一规则，不允许同类动作表现不一致。
- [ ] 移动状态只向 WeaponPresentation 提供姿态与速度数据，不把枪械表现重新堆回移动代码。
- [ ] 现有冲刺无敌帧必须重新核对；地面与空中共用同一充能，不允许重复恢复形成永久无敌。

### 2.5 碰撞与容错

- [ ] 使用胶囊体或等价连续碰撞，避免高速冲刺穿墙、穿楼板。
- [ ] 抓边检测包含前向探测、顶部空间检测和可站立面检测。
- [ ] 头顶空间不足时不得强行攀爬进模型。
- [ ] 墙跑只允许在标记为可墙跑的近垂直表面触发。
- [ ] 离开墙面时给予短暂输入宽限，减少动作无故中断。
- [ ] 被边缘或小装饰卡住时优先自动越过，而不是完全停下。
- [ ] Debug 显示 grounded、airborne、vault、mantle、wallRun、dash、slide 等移动状态。

## 3. P0：一张完整的三层立体城市地图

本轮直接制作完整 12 分钟地图，但控制为一个高密度街区，不扩张成开放世界。

### 3.1 总体规模

- 水平范围建议约 70×70 米，试玩后再根据敌人密度调整。
- 垂直分为三层：
  - 街道层：0～3 米。
  - 建筑中层：约 4～10 米。
  - 屋顶层：约 12～20 米。
- 三层提供的有效路线面积大于当前平面地图，但任意位置都不应长时间看不到敌人。
- 第一版不制作大量真实楼层，建筑主要提供外立面、屋顶和短通道。

### 3.2 四个识别地标

- [ ] 中央十字路口：主要街面战斗区和高密度经验区。
- [ ] 立体停车楼：宽缓坡道、楼层绕行和快速跳楼路线。
- [ ] 在建大楼与吊车：墙跑、脚手架、吊车桥和楼间跨越。
- [ ] 医院或商场停机坪：高层空投点、精英事件和终局高压区域。

地标需要明显不同的轮廓、颜色和灯光，使玩家不看小地图也能判断自己所在方向。

### 3.3 路线结构

- [ ] 每个高度层至少存在两条可以连续循环的路线。
- [ ] 三层之间至少设置 6 个有效连接点。
- [ ] 每个主要屋顶至少拥有两个玩家出口。
- [ ] 每个主要屋顶至少拥有一种敌人入侵方式。
- [ ] 不允许出现只有玩家能上、普通威胁永远无法到达的狙击台。
- [ ] 不允许大量死胡同；有死胡同时必须放置明确奖励或快速离开方式。
- [ ] 玩家从任意主要区域出发，10 秒左右应能找到至少两种高度变化选择。
- [ ] 所有关键路线都能用基础动作完成。
- [ ] 机动升级只能提供捷径、效率和战斗收益，不能解锁唯一必经道路。

### 3.4 环境路线元素

- 街道：车辆、公交车、集装箱、路障、店铺雨棚。
- 中层：广告牌、空调机、阳台、消防梯、脚手架、连廊。
- 屋顶：通风设备、水箱、吊车、停机坪、屋顶缺口。
- 快速装置：滑索、跳板、坠落缓冲棚、吊车钢索。
- 可破坏或变化元素第一版使用预设状态切换，不做真实物理破坏模拟。

### 3.5 可读性语言

- [ ] 可翻越边缘使用统一的高亮边条。
- [ ] 可墙跑表面使用统一的油漆、划痕或灯带。
- [ ] 滑索、跳板和攀爬锚点使用独立但一致的颜色。
- [ ] 装饰物不能伪装成可攀爬路线。
- [ ] 远距离能够看见下一段路线的落脚点。
- [ ] 路线标识主要存在于世界中，不依赖持续显示大量 HUD 箭头。

## 4. P0：12 分钟地图节奏与动态变化

开局即允许体验基础垂直移动；不要把真正的新玩法拖到数分钟后才开放。

### 4.1 0:00～3:00：认识城市

- [ ] 三层基础路线从开局即可到达。
- [ ] 敌人以普通感染者为主，少量展示攀爬行为。
- [ ] 通过尸潮位置自然诱导玩家第一次翻越、上楼和跳楼，不弹出长教学文本。
- [ ] 建筑中层暂时是较稳定的移动通道。
- [ ] 玩家在前 30～45 秒内应完成至少一次明显高度变化。

### 4.2 3:00～6:00：尸潮向上蔓延

- [ ] 正式加入攀爬感染者。
- [ ] 激活第一批滑索、跳板或吊车路线。
- [ ] 第一轮立体空投可以落在中层或屋顶。
- [ ] 触发一个路线开启事件，为现有路线增加捷径。
- [ ] 高处开始出现敌人，但不能突然把屋顶变成不可使用区域。

### 4.3 6:00～9:00：城市结构改变

从事件池半随机选择一至两个持久事件：

- 吊车旋转，形成新的楼间桥梁。
- 广告牌或脚手架倒塌，形成新的登楼斜坡。
- 巴士爆炸或建筑坠物，封堵一条街道路线。
- 感染气体、火焰或积液暂时淹没部分低地。
- 建筑外墙坍塌，打开新的攀爬路线。
- 电力恢复，启动一组跳板、升降平台或滑索。

- [ ] 事件改变真实路线和风险收益，不能只播放动画。
- [ ] 事件发生前有环境声音、灯光和地面提示。
- [ ] 任何封路事件都必须保留至少两条可用逃生路线。
- [ ] 变化后的路线在本局持续存在，让后半局空间记忆真正改变。

### 4.4 9:00～12:00：全立体追杀

- [ ] 攀爬怪、跳跃怪和远程怪组合出现。
- [ ] 地面仍保留高价值经验，不能让所有玩家只在屋顶结束游戏。
- [ ] 精英与空投将玩家引向不同高度。
- [ ] 11:00 后进入明显高压阶段，部分舒适路线被临时压制。
- [ ] 保留“存活 12 分钟”的现有胜利条件，本轮不增加强制撤离任务。
- [ ] 最后一分钟必须允许玩家继续自主选择路线，而不是被单一脚本赶往固定终点。

### 4.5 事件导演规则

地图事件不能每局在完全相同的秒数重复。

- [ ] 使用时间窗口而不是唯一固定秒数。
- [ ] 结合玩家所在区域、最近使用最多的路线和当前高度选择事件。
- [ ] 同一局避免连续两次只影响同一层。
- [ ] 事件不能在升级三选一、Boss 入场或玩家正在攀爬关键边缘时突然执行。
- [ ] 每局从事件池选择不同组合。
- [ ] Debug 可强制触发每个事件并显示触发理由。
- [ ] 记录每局触发了哪些事件、发生时间以及玩家当时所在区域。

## 5. P0：敌人的垂直追击与分层刷新

立体地图成立的底线：

> 高处只能提供暂时的节奏优势，不能成为永久安全区。

### 5.1 三类垂直威胁

#### 攀爬感染者

- [ ] 能沿预设攀爬锚点、墙面和脚手架从街道追到中层或屋顶。
- [ ] 攀爬前播放抓墙、撞击或嘶吼提示。
- [ ] 攀爬过程中可以被玩家射落。
- [ ] 到达平台后有很短的恢复时间，避免毫无反应窗口地直接命中玩家。

#### 跳跃感染者

- [ ] 能从相邻平台或楼顶跨越缺口扑向玩家。
- [ ] 起跳前显示姿态、声音和落点预警。
- [ ] 扑击失败后存在可惩罚窗口。
- [ ] 不允许从玩家完全看不见的位置无提示瞬移到身边。

#### 远程感染者

- [ ] 优先占据相邻屋顶、广告牌或高台。
- [ ] 用投射物或范围预警压制长期站桩。
- [ ] 攻击前有明显蓄力、弹道和落点提示。
- [ ] 作用是迫使玩家换位，不是持续制造无法躲避的伤害。

### 5.2 寻路实现

第一版不要求通用复杂三维 NavMesh，可使用可控的分层路线图：

- [ ] 为地图建立 street、mid、roof 三类导航区域。
- [ ] 使用 climb、jump、drop、stairs、zip 等连接边。
- [ ] 普通地面移动继续沿用当前二维移动逻辑。
- [ ] 只有抵达连接节点时进入攀爬、跳跃或坠落状态。
- [ ] 连接动作使用固定时长或速度，但视觉位置必须连续。
- [ ] 每个连接点标记允许通过的敌人类型。
- [ ] Debug 绘制导航区域、连接边、当前目标层和敌人路径。
- [ ] 路线失败时重新选路，不能长期堆积在墙脚。

### 5.3 分层刷怪导演

- [ ] 保留当前随时间增长的目标存活数量逻辑，不为展示新系统而无脑增加总怪量。
- [ ] 将目标数量按玩家高度和邻近层动态分配。
- [ ] 街道敌人从巷口、车辆、商铺遮挡后出现。
- [ ] 中层敌人从窗口、脚手架、破墙和楼梯间出现。
- [ ] 屋顶敌人从屋顶门、通风口和相邻建筑边缘出现。
- [ ] 所有刷新点必须在玩家视线外或被明确环境遮挡。
- [ ] 刷新点必须验证可达，不能把普通怪生成在永远下不来的装饰屋顶。
- [ ] 玩家快速跨层后，部分追兵继续追踪，部分威胁从目标层前方形成，避免尸潮全部被甩空。
- [ ] 不允许直接在玩家身后近距离生成普通怪解决追击问题。

### 5.4 防止屋顶站桩

当玩家在小范围或同一屋顶长时间停留时：

1. 先提高可见的攀爬压力；
2. 再加入跳跃截击；
3. 最后加入远程范围压制。

- [ ] 压力逐级增加，不在某个固定秒数突然刷脸。
- [ ] 玩家离开区域后压力逐步恢复。
- [ ] 普通高处停留本身不惩罚，只有长期无风险站桩才触发导演修正。
- [ ] Debug 显示 antiCamp 状态和当前采用的压制手段。

## 6. P0：三层空间的风险收益、经验与补给

三个高度层必须承担不同职责，否则玩家会找到唯一最优路线并永久重复。

| 高度 | 主要价值 | 主要危险 |
|---|---|---|
| 街道 | 敌人最多、经验最多、医疗机会较高 | 容易四面包围、路线容易被切断 |
| 建筑中层 | 连续移动最快、适合换位和整理尸潮 | 资源较少、前后夹击 |
| 屋顶 | 视野好、射击角度好、空投和精英奖励更常见 | 远程压制、跳跃截击、出口可能被封锁 |

### 6.1 经验处理

- [ ] 经验球记录所在高度，但吸附时能够跨越楼层。
- [ ] 玩家离开经验所在层后，经验经过短暂延迟自动进入跨层追踪。
- [ ] 大量经验不能永久堆积在楼下造成性能和心理负担。
- [ ] 跨层吸附路径可以穿过建筑几何，但表现上应快速、清楚，不长时间绕路。
- [ ] 经验球不得停在不可站立的墙面、空中或封闭模型内部。
- [ ] 统计未被拾取经验量、跨层吸附次数和最长滞留时间。

### 6.2 医疗掉落

- [ ] 继续使用 todo.md 已实现的 medicalNeed 自适应逻辑，不重写另一套系统。

## 7. P1：移动与枪械结合的共同变异

基础移动能力不进入随机池；三选一只改变“移动如何产生战斗收益”。

### 7.1 首批建议

| 变异 | 玩家效果 | 怪物对应变化 |
|---|---|---|
| 空中猎杀 | 弱点击杀刷新一次空中冲刺；每次滞空最多触发一次 | 跳跃怪扑击命中或落地后可以追加一次短跃 |
| 动量装填 | 完成翻越、滑铲或墙跑时补充部分弹匣 | 攀爬怪登上平台后获得短暂移速 |
| 坠落震荡 | 从足够高度落地时产生击退波 | 强壮怪获得带预警的跳跃砸地 |
| 壁行装甲 | 墙跑期间获得短暂护盾，离墙后迅速衰减 | 攀爬怪在墙面上获得短暂减伤 |
| 极速弹道 | 连续高速移动后，下一轮射击获得更清晰的穿透或冲击效果 | 高速感染者完成冲刺后的一次攻击强化 |
| 滑铲火线 | 滑铲路径留下短暂伤害区或强击退 | 冲刺类感染者移动后留下短暂危险区 |

### 7.2 卡面与实现纪律

- [ ] 卡面第一行说明玩家动作，第二行说明怪物获得什么。
- [ ] 卡面必须能在一次升级暂停内快速读懂。
- [ ] 玩家效果和怪物效果使用相同主题词与颜色。
- [ ] 不改变地图基础可达性。
- [ ] 不允许一次选择同时给怪物增加多个没有预警的新攻击。
- [ ] 新怪物动作接入现有背后威胁和攻击预警系统。
- [ ] 所有效果进入集中配置，可单独关闭玩家侧或怪物侧进行测试。
- [ ] 与 todo2.md 枪械表现事件对接，不另建第二套枪口、换弹或命中反馈。
- [ ] 首版先实装 3～4 个最清楚的变异，验证后再补齐整组。
- [ ] 钩索和大幅摆荡暂不进入首批变异。

## 9. 建议代码结构

文件名可以根据现有工程调整，但职责必须拆开，不能把全部逻辑继续堆进 game.js。

建议模块：

- movement.js：Y 轴、重力、跳跃、翻越、抓边、墙跑、冲刺、滑铲与状态机。
- citymap.js：立体地图构建、路线表面标记、落点与空投点。
- nav3d.js：敌人分层导航、连接边与攀爬锚点。
- map-events.js：12 分钟地图事件导演与状态切换。
- movement-mutations.js：机动共同变异及其玩家/怪物效果。
- render.js：环境、路线提示和三维标记的表现接入。
- tune.js：MOVEMENT、VERTICAL_MAP、VERTICAL_ENEMY、MAP_EVENT 等集中参数。

结构要求：

- [ ] 移动模拟、碰撞检测与视觉表现分离。
- [ ] 地图几何、导航数据和动态事件共享同一套区域/连接标识，避免三份坐标各自维护。
- [ ] 玩家和敌人的高度状态使用统一层级定义。
- [ ] 所有动态几何改变后同步更新碰撞、导航和落点验证。
- [ ] 对象池继续用于敌人、经验、提示和高频特效。
- [ ] Debug 能单独冻结敌人、地图事件或移动状态。
- [ ] 不让新模块反向拥有枪械伤害、升级抽取或 todo2.md 的表现状态。

## 12. 验收清单

### 完整性

- [ ] 新地图可以从 0:00 完整游玩到 12:00 并正常结算。
- [ ] 三选一、Boss、医疗、空投和现有共同变异均能正常运行。
- [ ] 关闭新增开关后，旧平面地图仍然可玩。
- [ ] 不存在频繁穿墙、穿地、卡边缘或掉出地图。

### 路线成立

- [ ] 玩家在前 45 秒内能够自然发现一次高度变化。
- [ ] 玩家无需升级即可抵达所有关键战斗区域。
- [ ] 每个主要屋顶至少有两个离开方式。
- [ ] 动态事件发生后，玩家需要重新判断路线。
- [ ] 不存在一条路线长期压倒所有其他路线。
- [ ] 不存在可以安全站满数分钟的屋顶或模型夹角。

### 尸潮压力

- [ ] 玩家上楼以后，尸潮不会全部丢失或永远留在地面。
- [ ] 攀爬怪、跳跃怪和远程怪都具有可见、可听、可反应的预警。
- [ ] 敌人不会在玩家身边无提示凭空出现。
- [ ] 快速跨层后仍有连续战斗，不出现长时间无怪可打。
- [ ] 防站桩导演逐级施压，而不是粗暴刷脸。

### 移动射击

- [ ] 玩家在跳跃、墙跑、空中冲刺和下落期间可以持续射击。
- [ ] 跑酷动作不会频繁取消换弹或吞掉射击输入。
- [ ] 空中射击依然能读懂枪口、弹道、命中和弱点反馈。
- [ ] 机动升级确实改变战斗方式，而不是只缩短赶路时间。
- [ ] 玩家不需要高强度搓招，也能连续完成一条立体路线。

### 资源与信息

- [ ] 经验不会大量永久滞留在不可返回的下层。
- [ ] 医疗和空投不会生成在不可达位置。
- [ ] 玩家能从 HUD 判断威胁或资源位于上方还是下方。
- [ ] 环境路线标识足以引导玩家，不需要铺满屏幕箭头。
- [ ] 高速移动时仍能听清攻击预警和玩家枪声。

### 性能

- [ ] 目标敌人数、连锁闪电、爆炸、分裂弹和垂直导航同时存在时保持当前性能目标。
- [ ] 动态地图事件不在运行时重复创建大量 Geometry、Material 或灯光。
- [ ] 敌人跨层导航不会因每帧全图寻路造成明显卡顿。
- [ ] 经验跨层吸附不产生大量长期存活对象。
- [ ] 完整 12 分钟没有持续增长的对象、监听器或定时器泄漏。

## 13. 本轮非目标

第一版不要：

- 制作开放世界或多个完整城区。
- 制作大量可进入楼层和复杂室内迷宫。
- 制作程序化城市生成。
- 制作真实建筑坍塌和物理破坏系统。
- 制作载具驾驶。
- 制作无限爬墙或无限滞空。
- 制作复杂钩索摆荡。
- 制作大规模飞行敌人。
- 改变“存活 12 分钟”的现有胜利条件。
- 重做 todo.md 已完成的医疗、空投、背后提示和弱点系统。
- 重做 todo2.md 的枪械表现方案。
- 为了赶工删除旧地图或把所有功能写死在同一个模式。
- 因为直接制作 12 分钟，就跳过阶段性运行、开关和验收。

## 14. 完成定义

本文件不是以“地图里出现高楼、玩家可以跳跃”为完成标准。

只有同时满足以下体验，才算改造成立：

1. 玩家会因为尸潮压力主动改变高度。
2. 玩家移动时仍然在持续射击和杀敌。
3. 街道、中层与屋顶各自拥有清晰的风险和收益。
4. 高处提供节奏优势，但不会成为永久安全区。
5. 十二分钟内地图会改变，玩家不能机械重复同一条路线。
6. 基础移动宽容、连续、有轻度超人感，但不要求专业跑酷操作。
7. 经验、医疗、空投、怪物和威胁提示全部理解三维高度。
8. 旧平面版本可以独立回退，本次大型改造不会破坏已有工作。

完成每项任务后在本文件中勾选；若实现中发现设计前提不成立，在对应条目下记录原因、测量结果和替代方案，不要只在提交信息里说明。
